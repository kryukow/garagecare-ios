# Правила разработки GarageCare

1. **Единственный источник приложения — `main`.** Не создавай ветки и PR без прямого запроса владельца. Не бери код старых версий из предыдущих разговоров: всегда читай текущий `main`.
2. **Версия = `project.yml`.** Каждая законченная пользовательская функциональная правка обновляет `MARKETING_VERSION` и монотонно увеличивает `CURRENT_PROJECT_VERSION`. После обновления проверь фактический номер в артефакте Actions.
3. **Нельзя терять существующие функции:** LPG/CNG/E85, моточасы, HU/TÜV, страховые платежи, сортировку работ, редактирование истории, отдельные фото работ и чеков, галереи, PDF/CSV, JSON backup/restore, локальные уведомления.
4. **Регламент:** для обычного ТО основной счётчик — километры, моточасы включаются явно. Календарный интервал остаётся только для HU/TÜV и старых календарных работ. Не показывай бессмысленное `0.0`; каждое числовое поле должно иметь понятную единицу измерения.
5. **Формы:** клавиатура должна сразу скрываться при прокрутке (`garageKeyboardDismiss()`), без дополнительной кнопки «Готово» над клавиатурой. Системные кнопки «Сохранить» в заголовках форм сохраняются.
6. **Миграции:** сохраняй Bundle ID `io.garagecare.app`, существующую SwiftData-схему и совместимость JSON-копий. Перед изменением хранилища добавляй тесты старых данных. Фото, чеки, дополнительные изображения и события не теряются.
7. **Безопасность:** никаких ключей, секретов подписи, личных данных, подписанных IPA и старого Interpreter в публичном репозитории.
8. **Сборка:** единственный `.github/workflows/build-ipa.yml` на Xcode 27: unit-тесты → unsigned IPA → артефакт с номером версии/build и SHA; UI-тесты доступны вручную. Не называй сборку готовой до зелёного Action и проверки имени артефакта.
9. **Публикация:** пользователь отказался от App Store. Не добавляй App Store/TestFlight/deploy workflow, бэкенд или подписки без запроса.
10. **Документация:** поддерживай один `README.md` и один `CHANGELOG.md`; не создавай отдельные changelog-файлы на каждую сборку.
